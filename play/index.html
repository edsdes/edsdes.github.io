春日 · 点心借阅
团长的点心，借得到吗？

    

      
      

    
登记处决定申请能不能通过，资料柜决定借哪一份。目标是在资料柜拿到 SOS 团的便签。卡住了就逐条问春日。

    
club 是社团：ordinary 普通部 / sos SOS 团。item=snack 是要借的点心条目。

      

    

    
便签夹在 SOS 的点心盒里。登记处却只肯借普通部的，真麻烦。

    
先递交默认申请，看看两个窗口的结果。200 只是处理成功；资料柜若读到 ordinary，拿到的还是普通部点心。
题目窗口 · GET /clubroom/cabinet?

    
desk 是未解码的参数列表，cabinet 是解码并合并同名参数后的最终结果。拿到便签时，note 里会出现 flag。

    

    

    
借一下 URL 小工具
只放想处理的参数名，不放整条申请。把输出用作新增参数的名字；原有 club=ordinary 保留。名称和值之间用 =，不同参数用 &。
按 UTF-8 字节写成 %XX，普通字母也会编码。工具只显示结果，不会自动改申请。

    
两个窗口的读法
登记处 desk 在原始字符串里检查参数名，不先做 URL 解码；原样重复的参数名会被拦下。
资料柜 cabinet 用 URLSearchParams 解码参数名和值；解码后出现同名参数时，取最后一项。例如 na%6De=tea 会读成 name=tea。对照两处规则，看看同一张申请在哪一步变了。

    

  


  

    

      
      
红莉栖 · 调试时间
让旧程序走进 win()

    

    

      
      

        

          
先别急，我陪你看。把地址放对以后，还要检查一下对齐。

          
        

        
选填充长度和返回地址。下面的内存会跟着变；地址放对以后，看看进入 win() 时还缺什么。

        
64 位教学模型：buf 16 字节 → 保存的 RBP 8 字节 → 返回地址 RIP 8 字节。win() 入口要求 RSP % 16 = 8。

      

    

    
baby-stack.c
char buf[16];
read_unchecked(buf);   // 模型里的输入函数，没有长度检查
// win() 里的 aligned_call 要求入口 RSP % 16 == 8
// ret() = 0x401016：多弹一个 8 字节地址

    

      
      

        
        
        
        字节
      

      
然后接上这个 8 字节地址
        
        
        
      

      
      
这个 ret() 会再弹出一个 8 字节地址，接着走向你选的目标。

    

    

      
缓冲区 buf · 16 字节

      
保存的 RBP · 8 字节

      
返回地址 RIP · 8 字节

      
下一个地址 · 8 字节

    

    
当前返回地址 0x401080

    read → ret → main()
    先调整返回地址，再检查 win() 的入口对齐。
    
技术提示
先数格子：16 字节 buf 后面，还有 8 字节保存的 RBP。返回地址从偏移 24 开始。
再选目标：让程序进入 win()。地址以小端序写入；淡紫色是填充，绿色是地址。
最后看对齐：直接返回 win() 时，入口 RSP % 16 = 0。让 ret() 先多弹一个 8 字节地址，再走到 win()，余数才会变成 8。这是本页的 64 位教学模型。
